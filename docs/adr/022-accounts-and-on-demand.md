# ADR-022: AWS のアカウントを staging と production で分け、どちらも使うときだけ作る

- 状態：決定
- 日付：2026-10-30

## 背景

AWS のアカウントの分け方と、環境を動かしておく時間を決める。ずっと動かすと、月 約100ドル以上かかる（S0-11 の見積もり）。

## 選択肢

| 選択肢 | 良いところ | 悪いところ |
| --- | --- | --- |
| アカウントを分け、どちらも使うときだけ作る | 費用を大きく下げられる。staging の操作で production を壊すことがない | 毎回、作るのと消すのに時間がかかる。production のデータを残すしくみが要る |
| 1つのアカウントに、両方を置く | 管理が楽 | 操作を間違えると、production を壊す。権限を分けにくい |
| ずっと動かす | いつでも使える | 費用が予算（月20ドル）を大きく超える |
| 夜だけ止める | 費用を少し下げられる | 止めている間も、ALB・NAT・RDS の保存などの費用がかかり続ける |

## 決めたこと

- アカウントは **staging と production で分ける**。今の作業用のアカウントを staging にし、production 用は S4-01 で Organizations に足す。予算と SCP（東京だけ）は、管理用のアカウントから全体にかける
- どちらも **使うときだけ作って消す**（`up` / `down`）。Terraform を「ずっと残す層」（state のバケット・ECR・シークレットなど）と「使うときだけの層」（VPC・NAT・ALB・ECS・RDS・ElastiCache など）に分ける（S1-19）
- production の `down` では、RDS の最後のスナップショットを取ってから消し、`up` では一番新しいスナップショットから戻す（S4-01b）。staging は毎回シードでよい

## 理由

- 費用を、月に数ドル〜10ドルほどに抑えられる（S0-11 の見積もり）
- アカウントを分けると、staging の操作で production を壊す事故が、しくみとして起きない
- 作って消すのを繰り返すので、Terraform で環境を作り直す練習にもなる

## 捨てた選択肢

- **1つのアカウント**：事故を防げないので採らない
- **ずっと動かす**・**夜だけ止める**：費用が予算に収まらないので採らない

## リスクと、その対策

- 消し忘れると、費用がかかり続ける。予算のアラートと、消し忘れを自動で消す仕組みを作る（S1-19）
- CLI のプロファイルを取り違えると、消すつもりのない環境を消す。`up` / `down` のスクリプトで、対象のアカウント ID を表示して確認してから実行する
