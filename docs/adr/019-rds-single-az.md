# ADR-019: RDS は Single-AZ にする

- 状態：決定
- 日付：2026-10-30

## 背景

RDS を、1つの AZ だけに置く（Single-AZ）か、2つの AZ に置いて、自動で切り替わるようにする（Multi-AZ）かを決める。

## 選択肢

| 選択肢 | 良いところ | 悪いところ |
| --- | --- | --- |
| Single-AZ ＋ 自動のバックアップ（PITR） | 費用が半分で済む | AZ の障害のときは、バックアップから戻すまで止まる（数十分） |
| Multi-AZ | AZ の障害でも、1〜2分で自動で切り替わる | 費用が約2倍になる |

## 決めたこと

staging も production も **Single-AZ** にする。自動のバックアップを有効にし、指定した時刻に戻せる（PITR）ようにする。サブネットグループは、2つの AZ にまたがるように作っておく（あとで Multi-AZ に変えやすくするため）。

## 理由

- このアプリは、staging も production も **使うときだけ動かす**（ADR-022）。ずっと動かし続けるサービスではないので、自動の切り替えの価値が小さい
- S0-11 の見積もりで、費用を下げるために Single-AZ にした

## 捨てた選択肢

- **Multi-AZ**：費用が約2倍になる割に、使うときだけ動かすこのアプリでは効果が小さいので採らない

## リスクと、その対策

- 要件定義書の可用性の目標（NFR-AVL）とは差がある。本格的に運用するときは、Multi-AZ にする
- バックアップから戻す手順を、Runbook に書き、一度は実際に試す
