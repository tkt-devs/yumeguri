# ADR-020: ローカルの S3・SQS の代わりに LocalStack（Hobby）を使う

- 状態：決定
- 日付：2026-10-30

## 背景

ローカルで開発するとき、本物の AWS の S3・SQS の代わりになるもの（エミュレーター）を Docker で動かす。2026年に、よく使われていたものの状況が変わった。

## 選択肢

| 選択肢 | 良いところ | 悪いところ |
| --- | --- | --- |
| LocalStack（無料の Hobby プラン） | コンテナ1つで S3 と SQS を両方まかなえる。AWS の SDK の接続先を変えるだけで使える | 2026年3月から、無料でもアカウントと auth token が必要。Hobby は個人・非商用だけ。止めるとデータが消える |
| MinIO（S3）＋ ElasticMQ（SQS） | アカウントが要らない | MinIO の無料版は、保守だけの状態になり、Docker のイメージも出なくなった |
| ElasticMQ ＋ RustFS など | アカウントが要らない | コンテナが2つになる。S3 との互換が一部だけ |
| 開発用の本物の AWS | 本物と同じ動き | 費用がかかる。ネットにつながらないと動かない。テストが遅い |

## 決めたこと

**LocalStack（Hobby）** を使う。イメージのバージョンは固定する。auth token は `.env` の `LOCALSTACK_AUTH_TOKEN` に入れ、CI 用の token は GitHub の Secrets に入れる。起動のたびに、init のスクリプトでバケットとキューを作る。

## 理由

- コンテナ1つで済み、設定が簡単
- このアプリは学習用で非商用なので、Hobby の条件に合う
- データが消えても、init のスクリプトで作り直す設計なので困らない

## 捨てた選択肢

- **MinIO ＋ ElasticMQ**：MinIO のイメージが出なくなったので採らない
- **ElasticMQ ＋ RustFS**：今は LocalStack で足りるので採らない（下の「対策」の切り替え先にする）
- **本物の AWS**：費用と速さが合わないので採らない

## リスクと、その対策

- LocalStack は、2026年に条件を変えている。また変わって使えなくなったら、**ElasticMQ ＋ RustFS** に切り替える
- token を Git に入れない（`.env` は `.gitignore` に入っている）
